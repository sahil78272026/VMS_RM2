## 2024-08-26 - VisitorLog N+1 Query Serialization Mitigation
**Learning:** The backend SQLAlchemy models have a recurring architectural pattern where `to_dict()` serialization triggers N+1 query performance bottlenecks on lazy-loaded relationships. Specifically, `VisitorLog.to_dict()` accessed multiple un-loaded relationships (`visitor`, `flat`, `flat_user`, `entry_gate`, `approved_by_flat_user`, and `approved_by_flat_user.user`), which resulted in a massive explosion of queries when fetching lists of visitor logs (like in `get_all_filtered`).
**Action:** Always inspect the model's `to_dict()` serialization logic to find heavily accessed relationships, and use SQLAlchemy's eager loading (`joinedload()`) on repository `get` methods (such as introducing a private `_base_query()` helper) to fetch those relationships in a single round-trip.
